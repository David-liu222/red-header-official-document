# 红头公文验收清单

## 自动检查

- [ ] 输出文件是新文件，源文件未被覆盖。
- [ ] 已先判断真实表格数量：`w:tbl=0` 时走无表格分支，`w:tbl>0` 时走有表格分支；报告写明分支结果。
- [ ] 文件名包含正文文号并与已有正文标题一致；任职迎检原稿无标题时文件名使用原名称/内容标签，正文不新增该标签。用户未传文号时已核查原稿唯一文号，多个不同文号没有自动选取。
- [ ] A4 页面；四边页边距落在目标范围或报告已记录偏差。
- [ ] 标题黑体二号、保留原有加粗，使用“正文文本/Normal”样式；在 WPS“段落”窗口中，段前、段后均明确显示为 `0 行`，不得显示为“自动”或 `0 磅`。
- [ ] 红头两行均用段落分散对齐，左右齐平且整体居中；宋体、45 磅、红色、加粗，无文本空格或首行手工字符字距；红头字体不得擅自替换为其他“常用公文红头字体”。
- [ ] 主送仿宋四号、加粗、顶格；一级独立小标题仿宋四号、加粗；普通正文、结束语、附件文字和落款保留原有加粗，原稿未加粗部分不新增加粗。未将独立小标题和完整序号条目混为一类。
- [ ] 含批注的原稿已提取批注原文与精确锚点，数量已核对；文本框和截图提示已另行查看，处理结果逐条记录，未把参考材料当操作授权。
- [ ] 源批注范围、引用、书签和业务附件在参考副本中保留；正式稿审阅痕迹按用途处理，不把不明对象静默删除。
- [ ] 已检查有效样式继承、字符单位间距与缩进、主题字体和复杂文字格式、段落标记及网格；表格有效样式未因全局修改Normal或节网格而改变。
- [ ] 主送及普通正文按有效样式左对齐，任职条目未整段居中；正文段前、段后均为 0，首行缩进约 2 字符。
- [ ] 正文、主送、结束语、落款和日期默认固定28磅；红头固定65磅、文号27磅、标题单倍；有表格局部例外须记录。
- [ ] 主送单位、外发/内发判断、迎检备注互相一致。
- [ ] 内发文已区分真实执行和迎检；迎检无签发人、末尾主题/抄报/抄送/发文/共印及配套黑横线；真实执行内发文保留所需栏目。
- [ ] 网页字段和原稿可见字段已比对；标题、文号、主送、落款、日期冲突已写入报告。
- [ ] 发文字号缺失时，输出文件和报告均明确标记为待补文号审阅稿。
- [ ] `outputMode` 已执行；默认只输出 DOCX，输出目录无 PDF；需要旧 DOC 时已转换或写明未能转换原因。
- [ ] 普通文稿序号没有跳级或混用；任职类迎检通知保留既有序号，不强制补“一、”或新增标题。
- [ ] 完整条目用句号结束；独立小标题和引出内容的冒号正确区分；书名号之间没有顿号。自动编号另核实际显示。
- [ ] 附件与结束语之间空一行；结束语无句号。
- [ ] 公司名、矿名/部门名和日期落款按规则分为独立段落，共用居中区域、恰好留一空行；无首行/悬挂字符缩进或定位空格/制表位，日期有效且无前导0。含分页、批注、域或对象的空段未作为普通空行删除。
- [ ] 无主送原稿在生成和校验均使用`--no-recipient`；普通正文加粗的当次明确覆盖在两者均使用`--body-bold`。
- [ ] `summary.failed=0`仅说明自动项无失败；`pending_manual`逐项处理并留证据，人工待核未被写成通过。自动失败返回1；需阻止未完成人工验收的自动任务使用`--require-manual-review`。
- [ ] 页码、红头和右下角落款按模板处理。
- [ ] 无表格分支未运行表格脚本、未写入表格分页/表头重复/行高/单元格属性。
- [ ] 有表格分支已分区处理：公文区按公文规则调整；表前说明与紧随表格分页联动；表格本体未套正文格式。
- [ ] 有表格分支已结构对比：表格文字、行数、单元格数、合并、列网格、斜线数量未变化；所有表格外框、内部横线、内部竖线、单元格边框和已有斜线边框均已强制为 `single` 实线；若任何表格内部行高/行距/列宽被改动，已有用户明确确认。
- [ ] 有表格分支已清理表格前残留空段落：紧贴 `w:tbl` 前不得有无正文、无分页符、无节属性的空 `w:p` 导致表前说明与表格之间出现异常大空白；不得删除含标题、说明、手动分页符或节设置的段落。
- [ ] 有表格分支不得残留 `w:tblpPr` 浮动定位/文字环绕；渲染后不得出现后续正文挤在表格左侧、竖向逐字换行、与表格并排绕排或重叠。
- [ ] 能整页容纳的表格未被拆页；不能整页容纳的表格跨页时保留或添加了原首行重复表头，且未复制新普通行、未拆成多张独立表。

## 人工渲染检查

- [ ] 红头颜色、红线、标题位置和主送单位位置正常。
- [ ] 红头两行按用户9月15日明确要求及80号定稿作分散对齐，字体字号一致；公司落款与日期共用同一居中区域，不是日期单独整页居中。
- [ ] 迎检文件未残留旧签发/印发文本框、表格或图形横线；红色分隔线、正文、公司落款及日期未被误删。
- [ ] 标题换行没有拆词，正文无压线、溢出、异常空白页。
- [ ] 页面视觉上“上长下短”，落款和日期没有挤到页底或脱离正文。
- [ ] 多页页码连续且位置一致。
- [ ] 附件编号、附件名称和分页符合用户要求。
- [ ] 旧 `.doc` 转换后字体没有替换、乱码或字形缺失；视觉验收使用页面图片或目标办公软件预览，不默认生成 PDF。

## 交付报告

交付时分成三组写明：

1. 已自动检查并通过的项目。
2. 已渲染、但需要人工目测确认的项目。
3. 因当前规则缺失或冲突而待用户确认的项目。

失败项单列，不并入已满足项。规则或脚本修改后，合成回归、引用链接与安装/维护/发布副本一致性均已核对。

网页任务还必须写明：

- 任务编号和来源文件数量。
- 使用的标题、文号、主送单位、发文类型、落款单位和成文日期。
- 输出文件清单；默认只列套红头 Word 文件，不列 PDF。
- 未确认字段不得写成“已满足”。

- [ ] 已用原稿副本按文字范围核对局部、整段和继承的加粗；保留原有强调，未扩大到整段。校验传`--source`，没有原稿时不宣称此项已通过。
- [ ] 任职迎检分支在生成和校验均使用`--appointment-notice --inspection-material`；原稿无标题时均加`--no-title`，文件名标签没有写入正文，原内容/序号没有改写。
- [ ] 落款后多余空白页已清理并重新渲染至最后一页；末尾空段/分页/空白分节已处理，真实附件及批注、书签、域和对象保留，只有页码/页眉的末页未作为有内容页通过。
